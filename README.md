## Структура

```
suction/           пакет проекта (слой 1 плана §5.1 — чистый Python, без ROS)
  config.py        IP, порты, топики, пути — единая точка правды
  arm/             клиент E6 по TCP (29999 / 30004)
  vacuum/          мост к Arduino: насос, клапан, поток давления
  camera/          RGB-D через ROS 2 (единственное место, где нужен rclpy)
  calib/           hand-eye (cv2.calibrateHandEye), интринсики
  dataset/         синхронный логгер трёх потоков, автосбор по сетке поз
  analysis/        признаки кривой давления, классификатор RQ1, метрики
tools/             запускаемые скрипты, разложены по функциям
  _lib/            общее: окружение, предполётная подготовка
  camera/          драйвер HP60C, сброс USB, проверки кадра
  arm/             связь с E6, аварии, присоска, движение
  calib/           ChArUco-доска и калибровка камера-рука
  measure/         оценка нормали и её ошибка (RQ2)
firmware/          скетч Arduino: I2C-датчик + управление насосом/клапаном
vendor/            внешние SDK (не в git)
data/              raw / calib / processed (не в git)
docs/              setup.md, hardware_bom.md
hardware/cad/      переходник под фланец E6
```

## Переносимость

Проект делится надвое по признаку «нужна ли камера».

| что | Linux со стендом | Windows / macOS |
|---|---|---|
| рука Dobot E6: связь, движение, присоска, аварии | да | **да** |
| решение hand-eye, генерация и проверка доски, вся математика | да | **да** |
| съёмка кадров, оценка нормали, проверки глубины | да | **нет** |
| сброс USB камеры | да | нет, выдёргивать кабель |

Блокер один и он не в коде проекта: драйвер Nuwa HP60C собран под Linux и
работает через ROS 2 Jazzy, а у Jazzy нет официальной сборки под Windows.
Переписать это можно только имея SDK камеры под Windows от производителя.

**Параметры калибровки переносимы полностью.** В `data/calib/handeye.json`,
`zone_baseline.json` и `charuco_board.yaml` лежат только числа — ни путей, ни
платформенных зависимостей. Их можно считать на одной машине, а использовать на
другой. Привязаны они не к ОС, а к физическому стенду: сдвинул камеру —
недействительны везде.

Запуск одинаков на всех системах:

```bash
python run.py                  # что вообще есть; звёздочкой отмечено Linux-only
python run.py arm check
python run.py calib solve
```

На Linux `run.py` вызывает обёртки `.sh` — в них чистка snap-переменных VS Code,
без которой падает Qt-бэкенд OpenCV. На Windows запускает скрипты напрямую:
bash там нет, а проблема со snap — линуксовая.

Машине без стенда нужен только `requirements-portable.txt`. **На машину со
стендом его ставить нельзя** — в нём `opencv-python`, который затенит системный
cv2 4.6.0 и уронит камеру.

## Быстрый старт

```bash
# камера (отдельный терминал, закрывать по Ctrl+C, не kill -9)
tools/camera/start.sh

# просмотр RGB-D
tools/camera/rgbd.sh

# ГЕЙТ ПРОЕКТА: годится ли глубина для оценки нормалей (план §12.1)
tools/camera/depth_check.sh

# печатная ChArUco-доска для hand-eye (робот не нужен)
python3 tools/calib/make_board.py
```

## Порядок работ

Порядок не переставлять — он выстроен так, что риск падает раньше вложений
(план §9, «хочется сделать всё сразу» — вероятность очень высокая).

| # | Шаг | Статус |
|---|---|---|
| 0 | Окружение, SDK, скелет | **готово** |
| 1 | Проверка точности глубины → судьба RQ2 | **частично**: RQ2 жив в центре кадра, найдено радиальное искажение. Осталась развёртка по дистанциям |
| 2 | Сокет к E6, движение из Python | нужен робот в сети |
| 3 | Arduino: датчик разрежения | нужен датчик и резьба штуцера ES01 |
| 4 | Hand-eye калибровка | доска напечатана и проверена, нужен робот |
| 5 | Синхронный логгер | после 2, 3 |
| 6 | Автосбор ~2000 попыток | после 5 |
| 7 | RQ1: классификатор по давлению | ← первый публикуемый результат |
| 8 | RQ2 → RQ3/RQ4 | |

Шаги 1 и 3 независимы от робота — их можно делать параллельно, пока едет железо.

## Заметки по окружению

См. [docs/setup.md](docs/setup.md). Коротко: ROS 2 Jazzy системный,
venv создан с `--system-site-packages`, `opencv-python` в venv **не ставить**
(затенит системный cv2 4.6.0, против которого собран `cv_bridge`).

# tools

Разложено по функциям. У каждого питоновского скрипта рядом обёртка `.sh` —
запускать нужно её, а не `python`: VS Code подмешивает snap-переменные, которые
ломают Qt-бэкенд OpenCV.

| каталог | про что |
|---|---|
| `_lib/` | общее: чистка окружения, предполётная подготовка |
| `camera/` | драйвер HP60C, сброс USB, проверки кадра и глубины |
| `arm/` | связь с Dobot E6, аварии, присоска, движение |
| `calib/` | ChArUco-доска и калибровка камера-рука |
| `measure/` | оценка нормали и её ошибка — измерители RQ2 |

## Соглашения

**Обёртки ничего не решают сами.** Вся логика в `.py`, обёртка только готовит
окружение через `tools/_lib/env.sh` и выбирает профиль:

- `plain` — рука, чистый python без ROS и без окон;
- `ros` — нужен `rclpy`, окон нет. `LD_LIBRARY_PATH` не снимается, на нём висит
  сам `rclpy`;
- `qt` — плюс окно OpenCV, `QT_QPA_PLATFORM=xcb`.

**Корень проекта ищется вверх по дереву** до каталога с пакетом `suction`, а не
через `parent.parent`: иначе переезд файла между каталогами ломает импорты.

**Скрипты, которые двигают руку, названы честно** и требуют подтверждения:
`arm/first_motion.sh`, `arm/park.sh`, `calib/capture.sh` (делает руку
податливой), `measure/pick_normal.sh --approach`.

**Имена окон OpenCV только латиницей.** С кириллицей Qt не находит окно, и
`setMouseCallback` падает молча — клики просто не доходят.

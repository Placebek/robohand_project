## 1. Железо: что реально стоит

Конфигурация отличается от исходного плана. План писался под сборку
пневмолинии с нуля; по факту на руке **серийный DOBOT ES01** — электрический
вакуумный узел, plug-and-play. Это переписало BOM и прошивку.

| Узел | Факт |
|---|---|
| Манипулятор | Dobot Magician E6, payload 750 г |
| Захват | **DOBOT ES01**: 55 кПа, 2.0 л/мин, 250 г, 24 В, управление по IO, обратной связи нет |
| Габариты ES01 | 74×65×65 мм (замерено: 6.5 / 5.3 / 7.4 см) |
| Чашка | наружный диаметр **35 мм** (не 15-20, как закладывал план) |
| Сопло | быстросъёмное, латунный штуцер с сетчатым фильтром внутри, под шестигранник |
| Камера | Nuwa/Angstrong HP60C, USB id `3482:6723`, 640×480, минимум 0.2 м |
| Сеть до робота | адаптер `enx00e04c680163` (RTL8152) воткнут, но **DOWN**; робот не подключён |

Из payload 750 г минус 250 г захвата остаётся **~500 г на объект**.

## 2. Измерено на камере (2026-09-03)

Сырые данные и скрипты анализа: `data/calib/depth_survey_20260903/`.

### Интринсики (из camera_info depth0)
```
fx = 584.1   fy = 583.1   cx = 320.0   cy = 274.8
угол обзора по горизонтали ≈ 57°
```
**Главная точка смещена вниз на 35 px от геометрического центра кадра.**
Камеру надо целить так, чтобы рабочая зона центрировалась на (320, 275).

### Поток здоров
- 24.7 Гц по `header.stamp`, 0 дубликатов из 59 пар подряд идущих кадров
- попиксельный шум по времени: median **0.30 мм**, p95 1.12 мм на 449 мм
- локальная плоскостность на пятне 35 мм: RMS **0.51 мм**

Шум отличный. Проблема не в нём.

### ГЛАВНАЯ НАХОДКА: радиальное искажение глубины

Плоскость подогнана по центру кадра, невязка посчитана по всему полю:

```
r =   0-60  px : median  -0.07 мм
r =  60-120 px : median  +0.16 мм
r = 120-180 px : median  -1.09 мм
r = 180-240 px : median  -6.97 мм
r = 240-300 px : median -11.89 мм
r = 300-400 px : median -19.44 мм

корреляция невязки с r² : -0.744
```

Карта глубины провалена чашей вокруг оптической оси. Это **систематика
камеры, а не форма листа** — проверено корреляцией с квадратом радиуса;
покоробленная поверхность такой картины дать не может. Усреднением не лечится.

Следствие для RQ2 — разброс нормали на пятне чашки 35 мм:
```
центр кадра (r<180 px):  median 2.84°   p95  5.39°   <- ОК, порог 5°
периферия   (r>180 px):  median 7.98°   p95 15.82°   <- мусор
```

**Рабочая зона ограничена кругом r < 180 px** вокруг главной точки.
На 449 мм это 138 мм радиуса, круг диаметром 277 мм.

### Открытое решение (спросить пользователя)
1. **Дёшево:** зафиксировать ограничение зоны r<180 px, записать в раздел
   ограничений, идти дальше.
2. **Правильно:** снять карту коррекции — плоский лист на 4-5 дистанциях,
   подгонка невязки как функции (r, z), вычитание из каждого кадра. День
   работы, возвращает весь кадр и даёт самостоятельный результат в статью.

Пользователь выбор пока не сделал. Данные для обоих путей собираются одни и те же.

### Калибровочная доска

measured_span_x_mm : 142.0

## 3. Грабли, на которые уже наступили

| Грабля | Как проявляется | Что делать |
|---|---|---|
| **Сцена ближе 0.2 м** | Глубина приходит целиком нулевой, БЕЗ ошибок в лог. Так потеряли час | Минимум считается до ближайшей точки сцены, не до стола. Держать 0.30-0.45 м |
| **Чёрное не измеряется** | ChArUco-доска пробивает в карте глубины дыры по своим чёрным квадратам | Доска годится ТОЛЬКО для RGB (hand-eye). Для гейта — однотонный матовый лист |
| **Qt ломается из VS Code** | `symbol lookup error`, окно OpenCV не открывается | Запускать через обёртки `tools/run_*.sh`, они чистят snap-переменные. Не `python tools/xxx.py` напрямую |
| **Драйвер камеры и kill -9** | SDK работает через libusb, устройство не освобождается | Останавливать только Ctrl+C |
| **opencv-python в venv** | Затенит системный cv2 4.6.0, против которого собран `cv_bridge` — камера отвалится | Не ставить. venv создан с `--system-site-packages` |
| **RGB-топик рваный** | `ros2 topic hz` за 8 с не ловит ни кадра, хотя подписчик за 15 с кадр получает | **НЕ РАЗОБРАНО.** Всплывёт при синхронном логгере |

## 4. Что сделано в коде

```
suction/config.py                    IP, порты, топики, пороги — единая точка правды
tools/start_camera.sh                драйвер HP60C (ROS 2 Jazzy)
tools/run_rgbd.sh                    просмотр RGB-D
tools/run_depth_check.sh             ГЕЙТ по глубине (RQ2)
tools/run_camera_plan.sh             таблица «дистанция → пятно/маркер/зона»
tools/make_charuco_board.py          генерация печатной доски (PIL, точный масштаб)
tools/verify_board_scale.py          проверка масштаба печати + перекрёстный контроль
firmware/suction_sensor/             прошивка под ES01: датчик + захват фронта DO
vendor/dobot_tcpip_v4/               Dobot TCP/IP SDK V4, установлен в venv (E6 поддержан)
```

Окружение: `.venv` с `--system-site-packages`, `from dobot_sdk import DobotRobot` работает.

### Прошивка: почему так
Arduino ничем не управляет — ES01 включает робот по IO. Arduino только меряет
давление и **ловит электрический фронт линии DO через оптопару PC817 на
прерывании D2**. Метка из контроллера робота по TCP имеет джиттер в единицы
миллисекунд, то есть того же порядка, что и измеряемый фронт нарастания
разрежения; аппаратный захват ставит t=0 в ту же шкалу, где лежат отсчёты.

Датчик XGZP6847D: адрес 0x6D, запись 0x0A в рег. 0x30, ожидание сброса бита
Sco (0x08), чтение 0x06-0x08 как знаковых 24 бит, `Па = ADC / 64`.
Регистры сверены с даташитом V2.5.

## 5. Блокеры

| # | Блокер | Кто снимает |
|---|---|---|
| 1 | **Резьба штуцера ES01 не замерена** | Пользователь: выкрутить, померить наружный диаметр и шаг (10 витков / 10), фото со штангенциркулем. Без этого не заказать переходник с отводом |

| 3 | **Робот не в сети** | Воткнуть кабель, поднять интерфейс, робот в режим удалённого TCP/IP (не DobotStudio) |
| 4 | **ES01 свой или кафедральный?** | Не отвечено. Если кафедральный — вскрывать нельзя, тогда основной сигнал берётся по току мотора (INA219 на переходнике к авиаразъёму), а не по давлению |

Подъём сети, когда дойдут руки:
```bash
sudo ip link set enx00e04c680163 up
sudo ip addr add 192.168.5.100/24 dev enx00e04c680163
ping 192.168.5.1          # LAN1; LAN2 — 192.168.100.1, Wi-Fi — 192.168.1.6
```

## 6. Дальше по порядку

1. **Доснять развёртку по дистанциям** (250/350/450/600 мм) и серию по наклону
   (0/10/20/30°) — `tools/run_depth_check.sh`. Даёт рабочую высоту подвеса и
   график «шум нормали от дистанции» в раздел ограничений.
2. **Решить: ограничение зоны или карта коррекции** (см. §2).
3. `arm_client.py` — TCP к E6, порты 29999/30004. Можно писать вслепую по SDK
   до подключения робота; предлагалось, пользователь не ответил.
4. Hand-eye калибровка. Доска на фланец, 15-20 поз. **Обязательно менять
   ориентацию, а не только положение** — на чистой трансляции AX=XB вырождается
   и даёт красивую невязку при полностью неверной матрице.
5. Прошивка + калибровка датчика (когда приедет).
6. Синхронный логгер трёх потоков → автосбор датасета → RQ1.

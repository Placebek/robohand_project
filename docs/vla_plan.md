## Зачем VLA, а не просто imitation learning

Научный руководитель просит именно VLA — модель, отображающую пару
«изображение + инструкция на языке» в действия, а не голую политику без
языкового входа (как ACT). Разница практическая: язык — это интерфейс задачи.
Одна политика, разные инструкции — разные объекты и цели, без переобучения
под каждую пару. Это и есть смысл буквы "L" в VLA, а не просто imitation
learning с картинкой на входе.

Выбранный инструмент — **SmolVLA через LeRobot** (HuggingFace). Причины:

- 450M параметров, обучается на потребительской видеокарте. Проверено:
  успешные дообучения на RTX 3060, 3050 Ti, 3080 Ti (12 ГБ). На 4070 Ti
  (12 ГБ) укладывается с запасом при batch size 16-32.
- Формат данных `LeRobotDataset` — Parquet + MP4 + JSON, с готовым Python API
  для записи (`LeRobotDataset.create/add_frame/save_episode`), не завязанным
  на конкретного производителя руки. Свой робот подключается без модификации
  библиотеки — пишем прямо через этот API, никакого драйвера LeRobot под
  Dobot E6 не требуется.
- Язык задачи хранится не отдельной веткой архитектуры, а строкой `task` в
  каждом кадре. Значит **многозадачность и языковое обобщение — бесплатны**:
  расширение с одной инструкции на несколько не требует переделки схемы,
  только новых демонстраций с другими строками `task`.
- Обучение и запись — разные машины. Запись (нужен только CPU) — на этом
  ноутбуке, рядом с рукой и камерой. Обучение (нужен GPU) — на любой из
  workstation с RTX 4070 Ti. Датасет между ними — обычный `rsync`, формат
  самодостаточен.

## Схема данных

Единая точка правды — [`suction/vla/schema.py`](../suction/vla/schema.py).

**Observation:**
- `observation.state` — 7 чисел: углы 6 суставов (`q_actual`, реальные
  показания энкодеров — см. `suction/arm/client.py`, ловушка `GetAngle`) +
  состояние присоски (0/1)
- `observation.images.top` — RGB с HP60C, 480×640×3

**Action:** те же 7 чисел, но **на следующем шаге**. При кинестетическом
ведении (drag-teach) нет отдельной "команды" — человек ведёт руку рукой,
есть только пройденная траектория. Стандартная практика для таких
демонстраций: `action[t] = state[t+1]`. Пары собираются при упаковке
(`raw.build_actions`), последний кадр эпизода отбрасывается — действия у него
нет.

### Запись идёт в два шага, а не в один

Первый вариант плана предполагал `add_frame` прямо в цикле записи. Так не
выйдет: `lerobot 0.6.1` требует `numpy>=2` и `opencv-python-headless`, а
`cv_bridge` из ROS Jazzy собран под numpy 1.x и без него нет камеры; headless
cv2 вдобавок не умеет `imshow`, то есть убивает окно записи. Один
интерпретатор обе стороны не вмещает — разбор и цифры в
[setup.md §7.1](setup.md#71-почему-на-ноутбуке-два-venv).

Поэтому:

```
tools/vla/record.sh   (.venv, ROS)  ->  data/vla_raw/<repo>/<эпизод>/
                                            frames/000000.jpg ...
                                            meta.json   (состояния, задача)
tools/vla/pack.sh     (.venv-lerobot)  ->  data/vla_datasets/<repo>/  (LeRobot)
```

Формат сырья — [`suction/vla/raw.py`](../suction/vla/raw.py). Выгода не только
в развязке зависимостей: демонстрация — физический труд человека у стенда, и
терять серию из-за исключения в чужой библиотеке посреди записи нельзя. Сырьё
переживает и обновление lerobot, и правку схемы полей: перепаковывается
заново сколько угодно раз. `meta.json` пишется последним и атомарно — эпизод,
прерванный на середине, упаковщик просто не увидит.

Упаковка идемпотентна: упакованные эпизоды помечаются `packed.json` и при
повторном запуске пропускаются. В конце обязателен `finalize()` — без него
`LeRobotDataset` остаётся в состоянии записи и не читается вообще
(`Cannot read from a dataset that is being recorded`), то есть обучение на
workstation упало бы на первом же обращении к датасету.

**Поза TCP не хранится отдельно.** Она однозначно выводится из углов прямой
кинематикой; дублировать — плодить рассинхрон при дообучении.

**Depth не подаётся политике.** Смысл VLA-трека — учиться действовать по
пикселям и языку напрямую, без явной геометрии. Depth, нормали и подгонка
плоскости остаются в Треке Б, где они как раз и есть предмет исследования.

## Почему НЕТ резервного столбца под давление

Соблазн — сразу добавить в `observation.state` нулевую восьмую позицию "под
давление", чтобы потом не переделывать схему. **Так делать не будем.**
Константный столбец не несёт сигнала; политика на нём либо научится его
игнорировать (тогда он просто лишний), либо, хуже, найдёт ложную корреляцию с
шумом инициализации весов. Ни то ни другое не помогает.

Правильный путь версионирования — новый `repo_id` датасета
(`e6-suction-pickplace-v2-pressure` вместо `-v1`) в момент, когда датчик
физически появится и в state добавится настоящее, а не нулевое число. Старый
датасет `-v1` при этом никуда не девается — это готовая RGB+proprioception
база, на неё дообучается всё то же самое.

## Порядок работ

1. **Задача и объекты.** Начинаем с одной: взять предмет со стола, положить в
   целевую зону. Payload после ES01 (250 г) — ~500 г, значит предметы лёгкие.
   Набор — 3-5 предметов, различающихся формой/цветом, чтобы у языкового входа
   было что различать («жёлтый кубик» против «синий цилиндр»).
2. **Запись демонстраций** — `tools/vla/record.sh --task "..."`. Ориентир по
   объёму: SmolVLA дообучают на десятках-сотнях эпизодов на задачу (не тысячи,
   как для более простых архитектур без предобученного backbone) — начать с
   50 на объект, смотреть по кривой обучения.
3. **Упаковка** — `tools/vla/pack.sh`. Можно после каждой сессии записи:
   дозапись в существующий датасет поддержана, повторный прогон ничего не
   задваивает.
4. **Перенос датасета на workstation** — `rsync -av data/vla_datasets/ workstation:~/...`.
5. **Дообучение** SmolVLA (`lerobot-train`, конфиг — когда датасет собран,
   писать конфиг вслепую бессмысленно).
6. **Перенос политики обратно, инференс на реальном роботе.** Здесь есть
   развилка: гонять инференс на ноутбуке (CPU, скорее всего медленно для
   450M на реальном времени — не проверено) или держать связь с workstation
   по сети во время исполнения. Решить по факту первого прогона.
7. **Оценка.** Success rate по объектам, по новым (не встречавшимся при
   обучении) формулировкам инструкции — языковое обобщение и есть то, ради
   чего выбран именно VLA, а не ACT.

## Что не меняется относительно прежней работы

Вся геометрическая инфраструктура используется без изменений: hand-eye
калибровка, `ArmClient`, проверка достижимости, драйвер камеры. Разница
только в том, что теперь она обслуживает не тычок по нормали, а запись
демонстраций и (позже) исполнение политики. Ничего из `suction/arm`,
`suction/calib`, `tools/camera`, `tools/calib` не тронуто и не устарело.

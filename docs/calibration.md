# Калибровка с нуля: порядок и что чем производится

Нужен после **любого** перемещения камеры. Проверить, двигали ли её, можно за
десять секунд: `tools/camera/zone_check.sh` сверится с эталоном и скажет прямо.

Каждый шаг производит файл, который нужен следующему. Пропускать нельзя —
получишь молчаливо неверный результат, а не ошибку.

```
  ставим камеру
        |
  [1] camera/zone_check.sh          -> прицел, повторять пока не чисто
        |
  [2] camera/zone_check.sh --save   -> data/calib/zone_baseline.json
        |                              ОТПЕЧАТОК: ловит будущий сдвиг камеры
  [3] calib/capture.sh              -> data/calib/handeye_ГГГГММДД/poses.json
        |                              18 поз: RGB-кадры + углы суставов
  [4] calib/solve.sh --data ...     -> data/calib/handeye.json
        |                              матрица камера -> база
  [5] calib/check.sh                -> ничего, только проверка
        |
  [6] measure/normal_error.sh       -> опорное число RQ2
        |
  готово: measure/pick_normal.sh
```

С этого момента **камеру не двигать**. Сдвинул — возвращайся к шагу 1.

---

## 1. Прицел

```bash
tools/camera/start.sh          # в отдельном окне, закрывать только Ctrl+C
tools/camera/zone_check.sh
```

Под камерой должен быть **пустой плоский стол**. Гоняй и правь положение
камеры, пока не станет так:

```
внутри круга: 100.0% валидных
остаток от плоскости: median ~0.5 мм, p95 ~1.5
дыр внутри круга нет
запас до далёких пикселей: +100 px и больше
```

Целься так, чтобы центр рабочей области попал в **пиксель (320, 275)** —
главная точка смещена на 35 px ниже центра кадра, и годный круг нарисован
вокруг неё, а не вокруг середины картинки.

Что означают плохие числа:

| симптом | причина |
|---|---|
| остаток десятки миллиметров | в круге не плоскость: предметы, край стола, база робота |
| дыры пятном | тёмный предмет (ИК не отражается) или мёртвая область камеры |
| дыры по всему кругу | мёртвая область: `tools/camera/reset.sh` при остановленном драйвере |
| «запас до далёких» отрицательный | край стола или пол залезли в рабочий круг |

## 2. Отпечаток

```bash
tools/camera/zone_check.sh --save
```

Пишет `data/calib/zone_baseline.json`: коэффициенты плоскости стола, глубину в
главной точке, наклон. Дальше любой прогон **без** флага сверяется с ним и
ругается при сдвиге больше 3 мм или 0.3°.

Это единственная дешёвая защита от того, что камеру заденут: сдвиг после
калибровки не проявляется ничем — матрица на месте, точки переводятся, рука
едет мимо.

## 3. Съёмка поз

```bash
tools/calib/capture.sh
```

Сам поднимает камеру и снимает аварию с руки. Доска — на лёгкой жёсткой
подложке, держит её присоска. Рука станет податливой, **держи её**.

Правила съёмки:

- меняй **ориентацию**, а не только положение. На чистых сдвигах вращательная
  часть `AX=XB` не определяется вовсе: уравнение выполняется при любой матрице;
- **разворот плашмя не заменяет крена.** Крутить доску вокруг оси взгляда
  камеры, как руль, легко и приятно: «макс. поворот» доходит до 90°, а набор
  при этом вырожден. Так был испорчен `handeye_20260907_1550` — 18 поз,
  медианный наклон 5°, третья/первая = 0.144. Нужен именно **крен**, когда
  плоскость доски отходит от плоскости кадра;
- кренить в **четыре стороны**, а не в одну. Скрипт после третьей позы печатает,
  сколько кренов больше 15° набрано вправо / влево / вверх / вниз по кадру, и
  прямо называет, в какую сторону завалить следующую позу;
- целься в **20+ углов** доски на позу. Круче наклон — лучше обусловленность,
  но доска частично уходит из кадра и её поза оценивается грубее. Держи её
  ближе к центру кадра и чуть дальше от камеры, чтобы при наклоне влезала
  целиком;
- **кисть крути плавно.** J6 самый лёгкий сустав, разгоняется незаметно, и
  контроллер режет по порогу скорости. Ловили дважды.

## 4. Решение

```bash
tools/calib/solve.sh --data data/calib/handeye_ГГГГММДД
```

Перебирает все двенадцать соглашений об углах Эйлера на пяти методах OpenCV и
выбирает по разбросу «фланец -> доска»: доска жёстко на фланце, значит это
преобразование обязано быть одним и тем же на всех позах.

Пишет `handeye.json` и копию `handeye_ГГГГММДД.json`. При замене решения другим
набором предупреждает.

Ориентир: **разброс до 5 мм и 2°**. Больше — смотри, что скажет диагностика:
если отклонение растёт с наклоном руки (корреляция выше 0.6), пружинит
крепление доски, и пересъёмка тем же способом не поможет.

## 5. Сквозная проверка

Доску положить **плашмя на стол**, лицом вверх, в рабочий круг.

```bash
tools/calib/check.sh
```

Три числа:

| что | ориентир |
|---|---|
| совмещение RGB и глубины | median до 8 мм |
| нормаль доски против оси инструмента | до 3° |
| разброс z по углам лежащей доски | до 5 мм |

Скрипт сам меряет наклон доски и отказывается делать выводы, если она не
плашмя, — иначе намеряешь её наклон и решишь, что сломана калибровка.

## 6. Опорное число RQ2

Под камерой — плоская поверхность. Раз она плоская, истинный наклон нормали
равен нулю, и всё намеренное есть ошибка метода.

```bash
tools/measure/normal_error.sh --save
```

Замер 2026-09-03: **median 2.93°, p95 7.19°**, за порог 5° выходят 14 % точек.
С этим и сравнивай.

## Что чем ломается

| действие | что становится недействительным |
|---|---|
| сдвинули камеру | всё начиная с шага 1 |
| перепечатали доску | `charuco_board.yaml`, шаги 3-6 |
| сменили инструмент на фланце | `TOOL_LENGTH_MM`, подвод руки; калибровка цела |
| переставили робота | всё |
| подвинули стол | только эталон зоны (шаг 2); калибровка цела |
